# 全興 EMS 出差工作紀錄

本目錄用來保存全興案場的每日工作、系統架構、批次流程與階段性總結。  
目錄分類於 2026/08/15 建立。（← 0815 新增）

## 目錄結構

```text
diary/
├─ README.md                 # 目錄使用說明
├─ SUMMARY.md                # 核心結論與每日完成事項
├─ 01_工作日誌/
│  ├─ YYYYMMDD_工作紀錄.md   # 每日工作紀錄
│  └─ images/                # 日誌使用的照片
└─ 02_系統文件/
   ├─ SYSTEM_ARCHITECTURE.md   # 系統整體架構
   ├─ BATCH_API_UI_MAPPING.md  # 批次、API 與畫面對照
   ├─ TROUBLESHOOTING_GUIDE.md # 問題排查流程
   └─ EMS_BATCH_OVERVIEW.md  # 完整批次程式盤點
```

## 各資料夾用途

| 位置 | 用途 |
|---|---|
| `SUMMARY.md` | 只放核心結論、文件索引、目前進度與每日完成事項。 |
| `01_工作日誌/` | 依日期保存當天做過的事情、測試內容、問題與待辦。 |
| `01_工作日誌/images/` | 保存工作日誌引用的現場照片與操作截圖。 |
| `02_系統文件/` | 保存可重複使用的技術知識，例如批次、API、資料庫與前端資料流。 |

## 紀錄方式

### 每日工作日誌

- 檔名使用 `YYYYMMDD_工作紀錄.md`。
- 建議分成：今日摘要、程式／系統、環境建置、硬體測試、待辦。
- 測試設備時，盡量記錄「測試條件、設定值、實際值、結果」。
- 尚未確認的內容標記為「待確認」，不要直接寫成已完成。

### 系統文件

- 架構、批次、API 與資料流等長期知識放在 `02_系統文件/`。
- 新增既有文件內容時，在標題或段落後標記 `← MMDD 新增`。
- 設備控制相關內容需特別註明讀取、寫入與可能影響。

### Summary

- `SUMMARY.md` 只保留最重要且已整理清楚的內容。
- 新增一天工作後，更新每日完成事項；有新的系統結論時，再更新架構與重點表格。
- 詳細操作過程留在每日工作日誌或系統文件，避免 Summary 過長。

## 紀錄注意事項

- 不在日誌中保存密碼、Token、私鑰或完整帳號資訊。
- 案場版本需分開記錄；全興／晉瑜不可誤用其他案場的批次或設定。
- 執行 PCS、BMS、保護或充放電測試前，先確認設備、點位、方向、限制值與停止條件。
- 這個目錄只保存文件與圖片，不放置或修改正式程式碼。
