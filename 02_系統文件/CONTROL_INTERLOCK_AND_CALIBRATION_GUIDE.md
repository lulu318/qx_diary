# ACB 操作、排程互鎖與 SOC 校正保護

建立日期：2026/08/18（← 0818 新增）

## 一、用途

保存 ACB 操作順序、充放電排程驗證、控制模式互鎖及 SOC 邊界校正的共同原則。實際門檻與設備編號仍以單線圖、BMS／PCS 文件及現場核准為準。

## 二、ACB 操作順序

| 動作 | 操作順序 | 每一步確認 |
|---|---|---|
| 開啟 | `B → A` | B 已完成合閘且回授正常，再操作 A。 |
| 關閉 | `A → B` | A 已完成分閘且回授正常，再操作 B。 |

停止條件：

- ACB 位置回授與命令不一致。
- 保護、跳脫或通訊告警未解除。
- 上下游狀態不符合互鎖條件。
- 不確定 A／B 實際設備身分或送電方向。

> 此順序為 08/18 現場測試紀錄。正式操作前仍需用單線圖確認 A／B 的設備名稱、上下游與機械／電氣互鎖。

## 三、控制防呆的責任分層

| 層級 | 應負責的檢查 | 原因 |
|---|---|---|
| Frontend | 即時提示時間重疊、欄位格式、明顯超限 | 提升操作體驗，但可被略過。 |
| Backend API | 驗證功率、時段重疊、SOC、模式衝突與設備限制 | API 是資料寫入的最後入口，必須作為正式防線。 |
| Batch／控制端 | 執行前重新確認模式、PCS／BMS 狀態與安全限制 | 設定完成後，設備狀態仍可能改變。 |
| 設備保護 | PCS／BMS／ACB 本體保護與硬體互鎖 | 最後一道設備安全保護。 |

結論：前端可以先擋，但後端與控制端不能假設請求一定來自前端。

## 四、Backend 必要驗證

| 驗證項目 | 建議規則 |
|---|---|
| 排程時間 | `start < end`，並使用一致時區。 |
| 時段重疊 | 同一設備、同一控制類型不得有交疊區間；是否允許相接需明確定義。 |
| 充放電方向 | 充電與放電不可同時生效；正負號定義須固定。 |
| 功率範圍 | 不得超過 PCS、案場及契約允許值。 |
| SOC 範圍 | 目標 SOC 必須位於案場允許區間內。 |
| 模式衝突 | 排程、抑低、超約、備轉、手動控制不得同時取得 PCS 控制權。 |
| 設備狀態 | PCS／BMS／ACB 未就緒、告警或通訊中斷時不得下功率。 |
| 重複請求 | 同一排程重送不應重複建立或重複下命令。 |
| 操作紀錄 | 記錄操作者、時間、原值、新值及拒絕原因。 |

### 時段重疊判斷

兩個排程 `[start1, end1)` 與 `[start2, end2)` 發生重疊的條件：

```text
start1 < end2 且 start2 < end1
```

建議使用左閉右開區間，如 `10:00～11:00` 與 `11:00～12:00` 可相接但不算重疊。

## 五、控制模式衝突

| 組合 | 處理原則 |
|---|---|
| 充電排程＋放電排程 | 後端直接拒絕重疊。 |
| 排程＋抑低 | 需先定義優先權；未定義前不得同時執行。 |
| 排程＋超約 | 需明確定義是否由超約暫時接管及如何恢復。 |
| 自動模式＋手動下功率 | 先取得控制權，未取得時拒絕操作。 |
| 任一控制＋設備保護 | 設備保護優先，功率歸零或停止控制。 |

前端可隱藏或停用衝突選項，但 Backend 仍需回傳明確錯誤，不能只接受後再由 Batch 猜測。

## 六、SOC 接近邊界的校正保護

### 接近 100%

- 進入上限區前開始降低充電功率。
- 以較小步階逐步接近目標，避免一次充電過頭。
- 若 BMS 禁充、單體電壓過高、溫度異常或告警，立即停止充電。

### 接近 0%

- 進入下限區前開始降低放電功率。
- 以較小步階逐步接近目標，避免過度放電。
- 若 BMS 禁放、單體電壓過低、溫度異常或告警，立即停止放電。

### 必須確認的參數

- 開始降速的 SOC 門檻。
- 每次降功率的步階與間隔。
- 最低允許充／放電功率。
- 完成校正與功率歸零的判定。
- 最長執行時間及通訊中斷處理。

這些參數沒有通用固定值，必須依設備規格、案場可用 SOC 範圍與實測結果設定。

## 七、兩日排程觀察清單

| 檢查點 | 通過條件 |
|---|---|
| 開始時間 | 在容許誤差內啟動。 |
| 結束時間 | 準時停止並將功率歸零。 |
| 功率方向 | 充電／放電方向符合排程定義。 |
| 功率數值 | 設定值、PCS 實際值與電表方向一致。 |
| SOC | 朝目標 SOC 變化，接近邊界時有降速。 |
| 工作模式 | 沒有被抑低、超約、手動或備轉非預期搶占。 |
| 告警 | 無新增異常；若有保護，設備動作符合預期。 |
| 復原 | 排程結束後模式與設備回到安全狀態。 |

## 八、待確認

- ACB A／B 的正式設備名稱與互鎖圖。
- Backend 目前缺少哪些排程與模式衝突驗證。
- 抑低、超約、排程與手動控制的正式優先權。
- SOC 上下限區的降速門檻、功率步階與校正完成條件。
